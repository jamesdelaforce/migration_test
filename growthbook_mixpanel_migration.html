Choose your migration path
GrowthBook supports the OpenFeature standard. The right path depends on how your codebase currently uses GrowthBook.
🔌
GrowthBook supports OpenFeature
GrowthBook provides official OpenFeature providers for JavaScript, Node.js, React, Go, and more. If your team is already using the OpenFeature SDK with the GrowthBook provider, migrating to Mixpanel is a single provider swap — no flag evaluation code changes needed anywhere in your codebase.
⚡ Path A — OpenFeature provider swap Fastest
Your codebase already uses @openfeature/growthbook-provider or similar. Swap the provider, update your project token and flag keys — all evaluation calls stay unchanged.
  • Install the Mixpanel OpenFeature provider
  • Replace the GrowthBook provider in your OpenFeature init
  • Update project token and flag keys if they differ
  • No changes to client.getBooleanValue() call sites
🔄 Path B — Full SDK migration Standard
Your codebase uses the native GrowthBook SDK directly (e.g. growthbook.isFeatureEnabled()). You'll swap to the Mixpanel SDK and update evaluation call sites.
  • Import flags into Mixpanel (steps 1–5 of this tool)
  • Install the Mixpanel SDK
  • Replace GrowthBook SDK init with Mixpanel init
  • Update flag evaluation calls to Mixpanel equivalents
Flag keys: As long as your flag keys in Mixpanel match the keys used in your OpenFeature / GrowthBook calls, no evaluation code changes are needed. Use steps 1–5 of this tool to import your GrowthBook flags into Mixpanel with the same keys.

Import to Mixpanel
Creates feature flags in Mixpanel, translating GrowthBook rules to Mixpanel rollout entries.
ℹ Rules translation — GrowthBook force rules with targeting conditions are translated to Mixpanel runtime_evaluation_rule (JsonLogic). Rollout rules map to rollout_percentage. Experiment-ref rules are flagged for manual linking. SavedGroup conditions are noted in the import log but cannot be auto-translated.
⚠ Default value mapping — GrowthBook's defaultValue becomes the Mixpanel control variant. All other values become treatments. For non-boolean flags, variation values are preserved in variant descriptions — Mixpanel flag variants use string keys.
